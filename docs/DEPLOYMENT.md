# Deployment

The site deploys to **Cloudflare Pages**. Static file requests there are free
and unlimited, and they're served from Cloudflare's global network, so traffic
spikes need no changes.

## One-time setup

### 1. Cloudflare Pages project

1. Sign in to Cloudflare and open **Workers & Pages**, then **Create**, then
   **Pages**, then **Direct Upload**.
2. Name the project `oxford-cloth-market`. This name has to match the deploy
   workflow.
3. Upload the `dist/` folder from `make build` for the first deploy.

### 2. Custom domain

1. In the Pages project, open **Custom domains** and add `oxfordclothmarket.com`
   and `www.oxfordclothmarket.com`.
2. Cloudflare shows the DNS records to create. Add them in **Squarespace
   Domains**, where the original Google Domains registration now lives.
3. Wait for both domains to show **Active**. HTTPS certificates are issued
   automatically.

### 3. Automatic deploys from GitHub

1. In Cloudflare, create an API token with the **Cloudflare Pages: Edit**
   permission. Copy your **Account ID** from the dashboard sidebar.
2. In GitHub, open **Settings**, then **Secrets and variables**, then
   **Actions**, and add:
   - `CLOUDFLARE_API_TOKEN`
   - `CLOUDFLARE_ACCOUNT_ID`

From then on:

- Every push to `main` runs the full test suite, then builds and deploys.
- A scheduled rebuild runs every morning, so past pop-ups drop off the page.
- Pull requests run the tests but never deploy.

Until both secrets exist, the deploy step is skipped and says so in the log.
Tests still run.

## What the host is told

`dist/_headers` is generated by `build.py`:

| Path | Headers |
| --- | --- |
| everything | Content-Security-Policy, Strict-Transport-Security, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy, Cross-Origin-Opener-Policy |
| `/assets/*` | cached for one year (file names change whenever content changes) |
| `/img/*` | cached for one day, served stale for up to a week while refreshing |

To allow a new third-party service, such as analytics or a newsletter
provider, update the policy in `security_headers()` in `build.py`. Don't edit
the generated file.

## Rolling back

Every deploy is kept in Cloudflare Pages. Open **Deployments**, choose an
earlier one and select **Rollback**. Or revert the commit on GitHub, and the
pipeline redeploys the previous version.
